File representation

The .vsn sidecar

A .vsn file is the revision sidecar associated with a logical file. For example, text.txt.vsn sits next to text.txt and carries its revision-related information.

The .vsn file is not the protocol itself. It is a file representation / sidecar used by the BinaryRevisionWithProtocol ecosystem.

  • One logical file maps to one sidecar.
  • Revisions are immutable and remain addressable according to retention policy.
  • Restore points at a revision, never rewrites it.

Design principles

Core principles

Small set of rules the protocol follows. No hidden behavior.

Immutable Revisions

Once written, a revision never changes.

Binary Safe

Text and binary content follow the same path.

Git Independent

No repository, index, or refs required.

Diff & Restore

Compare revisions and restore a prior state.

Transactional Changes

Multi-file changes apply together or not at all.

Crash Recovery

Interrupted work resolves to a known state.

Explicit File Identity

Each logical file carries a stable FileId.

Deterministic Encoding

Same input produces the same representation.

How it fits together

Architecture

Files on disk are a materialized projection. The canonical accepted state lives in the protocol's revision metadata and FileHead model.

  • Review a RevisionSet with diff before accepting.
  • Accepting advances the FileHead pointer.
  • Workspace projection renders the accepted state.

Vocabulary

Protocol concepts

The core terms used across the specification.

Revision
A single immutable snapshot of a logical file.
RevisionSet
A proposed group of revisions reviewed together.
FileHead
The pointer to the currently accepted revision.
ContentRef
A stable reference to stored content bytes.
DiffArtifact
The recorded difference between two revisions.
ApplyTransaction
The atomic step that applies accepted changes.
Logical Commit
The acceptance of a reviewed RevisionSet.
Workspace Projection
The materialized files rendered from accepted state.

Coexistence

Git independence

BinaryRevisionWithProtocol does not require a Git repository.

It addresses file revision and transactional workspace changes at the file level. It does not replace Git and can coexist with Git or other source-control systems.

  • With Git

    Sidecars version alongside sources; both histories remain separate.

  • Without Git

    Revisions, diff, and restore still work standalone.

  • Scope

    File revisions and workspace projection, not branching or remotes.
